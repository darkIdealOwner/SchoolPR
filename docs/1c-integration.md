# Интеграция SchoolPR с 1С

## Кто за что отвечает

| Данные | Где ведутся | Что делает другая сторона |
|---|---|---|
| Договоры, ученики, родители | Платформа | 1С забирает их и создаёт у себя контрагентов и договоры |
| Оплаты, принятые в школе (касса, терминал) | Платформа | 1С забирает их и проводит у себя |
| Оплаты на расчётный счёт, Click/Payme и т. п. | 1С | Платформа загружает их и учитывает в долгах |
| Зарплаты и прочие расходы | 1С | Платформа загружает их для дашбордов |

Связь между записями держится на **GUID объекта 1С** (`Ref_Key`). На платформе он хранится в поле `external_id`
у школ, сотрудников, договоров, оплат, выплат и транзакций.

Документы, пришедшие из 1С, на платформе **только читаются** (в списках у них метка «1С»).
Исправлять их нужно в 1С: изменения придут при следующем обмене. Документ, помеченный в 1С на удаление
или распроведённый, на платформе автоматически сторнируется. Если его снова провести, он вернётся в расчёты.

Каждый обмен записывается в журнал: страница **«Интеграция с 1С»** (у владельца на главной), а также
в админке, раздел «Обмены с 1С». Все изменения записей — в «Журнале действий».

## Порядок запуска

1. **Связать справочники.** Это делается один раз, потом только для новых записей.
   - Школы ↔ подразделения 1С: загрузить `schools` (см. формат ниже).
   - Сотрудники ↔ физлица 1С: загрузить `employees` (сотрудники берутся из справочника «Сотрудники» платформы,
     входить на платформу им не нужно).
   - Договоры ↔ договоры контрагентов 1С: загрузить `contracts`, либо 1С сама проставит GUID через API
     (`POST /api/1c/contracts/<id>/link/`).
2. **Пробно загрузить документы.** На странице интеграции выбрать файл и отметить «Пробный запуск».
   Ошибки покажут, какие договоры или школы ещё не связаны.
3. **Загрузить по-настоящему** и настроить регулярный обмен: командой по расписанию или через API из 1С.

## Каналы обмена

### 1. Файл (работает сразу, ничего настраивать не надо)

Выгрузите из 1С JSON-файл в формате ниже и загрузите его на странице «Интеграция с 1С» или командой:

```bash
python manage.py sync_1c payments --file payments.json --dry-run
python manage.py sync_1c payments --file payments.json
```

### 2. OData: платформа сама забирает документы из 1С

В 1С: «Администрирование → Обслуживание → Настройка стандартного интерфейса OData». Опубликуйте базу
на веб-сервере и отметьте документы `ПриходныйКассовыйОрдер`, `ПоступлениеНаРасчетныйСчет`,
`РасходныйКассовыйОрдер`, `СписаниеСРасчетногоСчета` и справочник `СтатьиДвиженияДенежныхСредств`.

В `.env` платформы:

```
ONEC_ODATA_URL=http://1c-server/school_buh/odata/standard.odata
ONEC_USER=odata
ONEC_PASSWORD=...
```

Запуск (например, раз в час через планировщик Windows или cron):

```bash
python manage.py sync_1c payments --odata
python manage.py sync_1c transactions --odata --since 2026-09-01
```

По умолчанию берутся документы за последние 60 дней. Повторная загрузка безопасна.

Имена документов и реквизитов в `integrations/onec.py` подобраны под типовую «Бухгалтерию предприятия».
Если в вашей конфигурации они называются иначе, правится только словарь `MAPPINGS` в этом файле.

### 3. API: 1С сама обращается к платформе

В `.env` задайте `ONEC_API_TOKEN` (длинная случайная строка). Каждый запрос из 1С идёт с заголовком
`Authorization: Token <токен>`.

| Метод и адрес | Назначение |
|---|---|
| `GET /api/1c/ping/` | Проверка связи |
| `GET /api/1c/contracts/?unlinked=1` | Договоры, ещё не связанные с 1С (`?updated_since=2026-10-01T00:00:00` — изменённые с даты) |
| `POST /api/1c/contracts/<id>/link/` `{"external_id": "GUID"}` | Сообщить GUID договора, созданного в 1С |
| `GET /api/1c/payments/?unlinked=1` | Оплаты, принятые на платформе и ещё не проведённые в 1С |
| `POST /api/1c/payments/<id>/link/` `{"external_id": "GUID"}` | Сообщить GUID документа, которым 1С провела оплату |
| `POST /api/1c/import/<тип>/` | Отправить документы 1С (тело — список записей или `{"records": [...], "dry_run": true}`) |

`<тип>`: `payments`, `payouts`, `transactions`, `schools`, `employees`, `contracts`.

Ответ импорта: `{"status": "SUCCESS|PARTIAL|FAILED", "created": 1, "updated": 0, "reversed": 0, "failed": 0, "errors": [...]}`.

## Форматы записей

Общие поля документов:

- `external_id` — GUID документа в 1С, **обязателен**;
- `deleted` — `true`, если документ помечен на удаление;
- `posted` — `false`, если документ не проведён.

Документ с `deleted: true` или `posted: false` сторнируется.

Даты — `YYYY-MM-DD` (или `YYYY-MM-DDTHH:MM:SS`, `DD.MM.YYYY`). Суммы — числом или строкой, разделитель дробной
части — точка или запятая.

### payments — оплаты родителей

```json
[
  {
    "external_id": "8f0c2c1e-5b8e-11ef-9a5b-00155d000001",
    "contract_external_id": "1a2b3c4d-0000-0000-0000-000000000030",
    "contract_number": "30",
    "payment_date": "2026-10-05",
    "for_month": "2026-10",
    "amount": "2027000.00",
    "method": "BANK",
    "notes": "ПКО №125"
  }
]
```

- Договор ищется по `contract_external_id`, иначе по `contract_number`.
- `for_month` — за какой месяц оплата. Если не указан, берётся месяц `payment_date`.
- `method`: `CASH`, `CARD`, `CLICK`, `PAYME`, `UZUM`, `BANK`. По умолчанию `BANK`.

### payouts — выплаты сотрудникам

```json
[
  {
    "external_id": "…",
    "employee_external_id": "GUID физлица",
    "employee_phone": "+998901234567",
    "school_external_id": "GUID подразделения",
    "payout_date": "2026-10-10",
    "for_month": "2026-09",
    "amount": 3500000,
    "notes": "Зарплата за сентябрь"
  }
]
```

Сотрудник ищется в справочнике сотрудников по `employee_external_id`, иначе по `employee_phone` (телефон карточки
или пользователя). Если школа не указана, берётся школа сотрудника.

### transactions — прочие приходы и расходы

```json
[
  {
    "external_id": "…",
    "school_external_id": "GUID подразделения",
    "school_name": "школа №1",
    "type": "EXPENSE",
    "category": "Коммунальные услуги",
    "date": "2026-10-12",
    "amount": "850000",
    "notes": "Электроэнергия, октябрь"
  }
]
```

`type`: `INCOME` (приход / инвестиция) или `EXPENSE` (расход). `category` — название статьи: ищется в справочнике
статей платформы на любом языке; если такой нет, запись попадает в «Прочие», а название статьи 1С — в примечание.

### schools, employees, contracts — связка справочников

Записи только проставляют GUID 1С уже существующим школам, сотрудникам и договорам. Новых не создают.

```json
[{"external_id": "GUID подразделения", "name": "школа №1"}]
[{"external_id": "GUID физлица", "phone": "+998901234567"}]
[{"external_id": "GUID договора контрагента", "number": "30"}]
```

## Где это в коде

- `users/models.py` — `ExternalSyncMixin`: поля `external_id`, `source`, `synced_at`.
- `integrations/importers.py` — разбор записей, создание, обновление и сторно, журнал обменов.
- `integrations/onec.py` — клиент OData и сопоставление документов 1С.
- `integrations/api.py` — API для 1С.
- `integrations/management/commands/sync_1c.py` — команда обмена.
- `users/finance.py` — все денежные расчёты. Загруженные из 1С документы попадают в них автоматически.
